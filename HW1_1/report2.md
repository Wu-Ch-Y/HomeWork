# 作業一：Problem 2 — Powerset（冪集）

## 1. 解題說明

### 問題描述

若 $S$ 是一個有 $n$ 個元素的集合，$S$ 的 **powerset**（冪集）是「 $S$ 所有可能子集合」所組成的集合。例如 $S=\{a,b,c\}$ 時：

$$
\text{powerset}(S)=\{(\ ),(a),(b),(c),(a,b),(a,c),(b,c),(a,b,c)\}
$$

題目要求：寫一個**遞迴函式**來計算 $\text{powerset}(S)$。

### 解題策略

觀察：對於 $S$ 中的每一個元素，只有兩種選擇：

- **放進**子集合
- **不放進**子集合

所以 $n$ 個元素共有 $2^n$ 個子集合。

遞迴的想法是：從第 `i` 個元素開始，一個一個決定「選或不選」。

1. **終止條件**：`i` 等於元素總數，代表所有元素都決定完了，把目前選到的元素 `cur` 印出來，這就是一個子集合。
2. **遞迴情況**：對第 `i` 個元素
   - 不選：呼叫 `powerset(s, i+1, cur)`
   - 選：呼叫 `powerset(s, i+1, cur + s[i])`

這個過程可以想成一棵二元樹：第一層決定 `a` 選不選，第二層決定 `b`，第三層決定 `c`，每條從根走到葉的路徑就是一個子集合。

由於作業限制只能使用指定的標頭檔（沒有 `<vector>`），所以用 `string` 來存集合的元素和目前選到的元素。

另外，`cur + s[i]` 會產生一個**新的字串**，原本的 `cur` 不會被改動，所以不需要再「還原」（回溯）的動作，程式比較簡單。

## 2. 程式實作

```cpp
#include <iostream>
#include <string>
using namespace std;

int cnt = 0;   // 記錄印出了幾個子集合

// s：原本的集合，i：現在看到第幾個元素，cur：目前選到的元素
void powerset(string s, int i, string cur) {
    if (i == s.length()) {           // 全部元素都決定完了，印出這個子集合
        cout << "(";
        for (int k = 0; k < cur.length(); k++) {
            cout << cur[k];
            if (k != cur.length() - 1) cout << ",";
        }
        cout << ")" << endl;
        cnt++;
        return;
    }

    // 情況一：不選 s[i]
    powerset(s, i + 1, cur);

    // 情況二：選 s[i]
    powerset(s, i + 1, cur + s[i]);
}

int main() {
    string tests[5] = { "abc", "ab", "a", "", "abcd" };

    for (int t = 0; t < 5; t++) {
        cout << "S = {";
        for (int k = 0; k < tests[t].length(); k++) {
            cout << tests[t][k];
            if (k != tests[t].length() - 1) cout << ",";
        }
        cout << "}" << endl;

        cnt = 0;
        powerset(tests[t], 0, "");
        cout << "共 " << cnt << " 個子集合" << endl << endl;
    }
    return 0;
}
```

## 3. 效能分析

設集合有 $n$ 個元素。

**時間複雜度**

- 遞迴呼叫的總次數：每一層的呼叫數是上一層的兩倍，總共 $1+2+4+\cdots+2^n = 2^{n+1}-1$ 次，也就是 $O(2^n)$ 次。
- 每次呼叫要複製字串 `s`、`cur`，最後印出子集合也需要 $O(n)$。
- 所以總時間複雜度為 $O(n \times 2^n)$。

**空間複雜度**

- 遞迴深度為 $n+1$ 層。
- 每一層都保存了 `s` 和 `cur` 的副本（各約 $O(n)$）。
- 所以空間複雜度為 $O(n^2)$。

（若改成用參考傳遞 `const string& s`，可以省掉複製 `s` 的成本，空間可降到 $O(n)$。）

由於答案本身就有 $2^n$ 個子集合，輸出量就是指數成長，所以時間複雜度是指數級是**無法避免**的。

## 4. 測試與驗證

編譯與執行：

```shell

S = {a,b,c}
(),(c),(b),(b,c),(a),(a,c),(a,b),(a,b,c)
共 8 個子集合

S = {a,b}
(),(b),(a),(a,b)
共 4 個子集合

S = {a}
(),(a)
共 2 個子集合

S = {}
()
共 1 個子集合

S = {a,b,c,d}
(),(d),(c),(c,d)
(b),(b,d),(b,c),(b,c,d)
(a),(a,d),(a,c),(a,c,d),(a,b),(a,b,d),(a,b,c),(a,b,c,d)
共 16 個子集合
```

驗證：

| 集合 $S$ | 元素個數 $n$ | 應有子集合數 $2^n$ | 程式輸出 | 是否正確 |
|---|---|---|---|---|
| $\{a,b,c\}$ | 3 | 8 | 8 | true |
| $\{a,b\}$ | 2 | 4 | 4 | true |
| $\{a\}$ | 1 | 2 | 2 | true |
| $\{\}$（空集合） | 0 | 1 | 1 | true |
| $\{a,b,c,d\}$ | 4 | 16 | 16 | true |

說明：

- 每個 $S$ 的輸出都包含空集合 `()` 和 $S$ 本身。
- 子集合的內容沒有重複，也沒有遺漏，與題目範例 $\{a,b,c\}$ 的 8 個子集合完全相同（只是印出的順序不同，因為本程式是「先不選、再選」的順序）。
- 空集合的 powerset 只有一個元素，就是空集合本身，符合 $2^0=1$。

## 5. 申論及開發報告

**為什麼用遞迴？**
求 powerset 的過程可以拆成相同的小問題：決定完第 1 個元素後，剩下的就是「對剩下 $n-1$ 個元素求 powerset」。問題結構自己包含自己，所以用遞迴寫最自然，程式也很短。

**為什麼用「選或不選」的想法？**
每個子集合都可以表示成「對每個元素做一次選或不選」的結果，這樣不會重複，也不會漏掉，剛好對應到 $2^n$ 個子集合。這比「先找所有大小為 0 的、再找大小為 1 的……」的寫法簡單。

**為什麼用 `string` 而不是 `vector`？**
作業規定只能使用指定的標頭檔，`<vector>` 不在其中，但 `<string>` 可以用。`string` 可以存字元、用 `+` 接上新字元，足以表示「元素是單一字元」的集合。

**為什麼不需要回溯？**
`cur + s[i]` 會建立新的字串，原本的 `cur` 不受影響，所以從「選」的分支回來之後，`cur` 仍然是還沒選的狀態，不需要再手動還原。

**心得與限制**
- 這題的輸出數量是 $2^n$，所以 $n$ 稍大（例如 $n>25$）就會跑得非常慢，這是問題本身的性質，不是程式寫得不好。
- 目前只支援「每個元素是一個字元」的集合；如果元素是數字或字串，需要改用其他資料型態儲存。
- 這題讓我體會到遞迴的重點是「把大問題拆成同樣形式的小問題」，並找到明確的終止條件。
