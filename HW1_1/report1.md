# 作業一：Problem 1 — Ackermann 函數

## 1. 解題說明

### 問題描述

Ackermann 函數 $A(m,n)$ 定義如下：

$$
A(m,n)=
\begin{cases}
n+1 & \text{，if } m=0 \\
A(m-1,1) & \text{，if } n=0 \\
A(m-1,\,A(m,n-1)) & \text{，otherwise}
\end{cases}
$$

這個函數的特色是，即使 $m$、$n$ 很小，數值也會成長得非常快。題目要求：

1. 寫出計算 Ackermann 函數的**遞迴**函式。
2. 寫出計算 Ackermann 函數的**非遞迴**演算法。

### 解題策略

**(a) 遞迴版**

直接照定義寫，三種情況對應三個 `if`：

- $m=0$：回傳 $n+1$
- $n=0$：回傳 `ack(m-1, 1)`
- 其他：回傳 `ack(m-1, ack(m, n-1))`

**(b) 非遞迴版**

第三種情況 $A(m-1, A(m,n-1))$ 的意思是「先算內層 $A(m,n-1)$，算完後再用結果去算外層 $A(m-1,\ ?)$」。遞迴版會由系統的呼叫堆疊（call stack）自動記住「外層還沒做的事」，所以非遞迴版要自己用 **stack** 來記。

stack 只存「待處理的 $m$ 值」，$n$ 則用一個變數不斷更新：

1. 一開始把 $m$ 放進 stack。
2. 當 stack 不是空的，拿出最上面的 $m$：
   - $m=0$：`n = n + 1`
   - $m>0$ 且 $n=0$：`n = 1`，並把 `m-1` 放進 stack
   - 其他：先放入 `m-1`（外層，等一下再做），再放入 `m`（先去算內層），並讓 `n = n - 1`
3. stack 空了，$n$ 就是答案。

標頭檔限制只能使用 `<iostream>` 等指定標頭，不能用 `<stack>`，所以用**陣列 + top 變數**來模擬 stack。

## 2. 程式實作

```cpp
#include <iostream>
using namespace std;

// ---------- 遞迴版 ----------
int ack(int m, int n) {
    if (m == 0) {
        return n + 1;
    }
    if (n == 0) {
        return ack(m - 1, 1);
    }
    return ack(m - 1, ack(m, n - 1));
}

// ---------- 非遞迴版（用陣列當 stack）----------
int st[100000];   // 用陣列模擬 stack
int top = 0;      // 目前放了幾個，也是下一個要放的位置

int ack2(int m, int n) {
    top = 0;
    st[top] = m;      // 先把 m 放進 stack
    top++;

    while (top > 0) {     // stack 不是空的就繼續
        top--;            // 拿出最上面的 m
        m = st[top];

        if (m == 0) {
            n = n + 1;
        }
        else if (n == 0) {
            n = 1;
            st[top] = m - 1;
            top++;
        }
        else {
            st[top] = m - 1;   // 外層還沒做的事，先存起來
            top++;
            st[top] = m;       // 先去算內層 ack(m, n-1)
            top++;
            n = n - 1;
        }
    }
    return n;
}

int main() {
    int tests[6][2] = { {0, 0}, {1, 1}, {2, 3}, {3, 3}, {3, 5}, {2, 0} };

    for (int i = 0; i < 6; i++) {
        int m = tests[i][0];
        int n = tests[i][1];
        cout << "A(" << m << "," << n << ")  遞迴 = " << ack(m, n)
             << "  非遞迴 = " << ack2(m, n) << endl;
    }
    return 0;
}
```

## 3. 效能分析

Ackermann 函數不是一般的多項式複雜度，它的執行時間和空間都跟**函數值本身**有關，所以下面依 $m$ 的大小分開討論：

| $m$ | 函數值 | 時間複雜度（呼叫次數） | 空間複雜度（遞迴深度 / stack 大小） |
|---|---|---|---|
| 0 | $n+1$ | $O(1)$ | $O(1)$ |
| 1 | $n+2$ | $O(n)$ | $O(n)$ |
| 2 | $2n+3$ | $O(n^2)$ | $O(n)$ |
| 3 | $2^{n+3}-3$ | 約 $O(4^n)$ | $O(2^n)$ |
| $\ge 4$ | 超級巨大 | 增長速度遠超指數 | 增長速度遠超指數 |

說明：

- **時間複雜度**：兩個版本做的事情完全相同，只是「誰來記住外層工作」不同（系統 stack 或自己的陣列），所以時間複雜度相同。
- **空間複雜度**：遞迴版是系統呼叫堆疊的深度，非遞迴版是陣列 `st` 同時放了多少個 $m$，兩者量級相同。
- 非遞迴版的陣列大小固定為 100000，當 $m \ge 3$ 且 $n$ 太大時，stack 會放不下，需要加大陣列，或在 $m$、$n$ 過大時不要測試。

## 5. 申論及開發報告

**為什麼用遞迴？**
Ackermann 函數本身就是用遞迴定義的，直接照定義寫成遞迴函式最直覺，程式碼和數學式幾乎一一對應，不容易寫錯。

**為什麼用 stack 改寫成非遞迴？**
遞迴的本質是系統用「呼叫堆疊」記住「還沒做完的事」。觀察第三種情況 $A(m-1, A(m,n-1))$：必須先算完內層，才能做外層，這正是「後進先出」的行為，剛好適合用 stack。把待處理的 $m$ 放進 stack，就能自己模擬遞迴的過程。

**為什麼 stack 只需要存 $m$？**
每次呼叫的「結果」都會傳給下一層當作新的 $n$，所以 $n$ 只需要一個變數持續更新；真正需要記住的只有「接下來還要用哪個 $m$ 去算」。

**為什麼用陣列而不是 `<stack>`？**
作業規定只能使用指定的標頭檔，`<stack>` 不在其中，所以用陣列加上 `top` 變數自己實作 stack。放入就是 `st[top] = 值; top++;`，取出就是 `top--; 值 = st[top];`。

**心得與限制**
- Ackermann 函數成長極快，$m \ge 4$ 的結果會超過 `int` 的範圍，遞迴版也會因為遞迴太深而 stack overflow。
- 非遞迴版不會因為系統堆疊不足而當掉，但仍受限於陣列大小，這是這個函數本身的特性，不是演算法的缺點。
- 這題讓我體會到遞迴和 stack 的關係：任何遞迴都可以用 stack 改寫成迴圈。
